Phase 1 — Critical bug fixes
May 28–29  ·  Day 1–2
Must fix first
Three active crashes found in your logs
1. 'charmap' codec can't encode '\U0001f4ca' — FastF1 emits the 📊 emoji in its log output; Windows stdout uses cp1252 by default and can't encode it → every fresh API call returns HTTP 500
2. WinError 10048 — port 8000 still bound when server restarts; previous process not cleaned up
3. pick_driver is deprecated — FastF1 3.x renamed it to pick_drivers; will break in future release
Fix charmap encoding crash
Add sys.stdout.reconfigure(encoding='utf-8') at top of main.py, and redirect FastF1's logging through a UTF-8 handler. This is the root cause of every 500 error on fresh data loads.
criticalbackend
Fix port binding on restart
Add socket reuse option to uvicorn config or use a port cleanup utility on startup. Prevents the need to manually kill processes when restarting the server during development.
criticalbackend
Update deprecated FastF1 API
Replace all pick_driver() calls with pick_drivers() throughout the backend. Also audit for any other deprecated calls in FastF1 3.6.x.
backend
Verify fixes with end-to-end smoke test
Hit /api/race-data/2024/Bahrain/R without cache. Confirm 200 OK. Then delete cache and confirm it rebuilds cleanly. Only move to Phase 2 when this passes reliably.

Phase 2 — Dynamic data pipeline
May 30–31  ·  Day 3–4
Core goal
Race schedule endpoint
New GET /api/schedule/{year} that returns all races with name, round, date, and a available boolean (true if race has finished and FastF1 data exists). Frontend uses this to populate the race selector.
backenddata
Auto-refresh cache for new races
Background task that runs every 6 hours post-race Sunday. Checks if a race completed (session end time passed), pulls FastF1 data, processes it, and saves to cache. Monaco GP data lands automatically after the race.
backenddatainfra
Race availability checker
Utility function that queries FastF1 / OpenF1 to verify a session has finished and telemetry data is available before attempting to load. Prevents 500s on "race in progress" or "race not yet happened" requests.
backenddata
Harden cache layer
Cache invalidation strategy: cache is valid for completed races forever, invalid for races from the last 12 hours (might still be updating). Add a cache manifest endpoint for the frontend to know what's pre-processed.
backendinfra
Phase 3 — Frontend overhaul
June 1–2  ·  Day 5–6
Friends-facing
Your friends will judge the project by the UI first. A polished frontend hides backend roughness. Prioritise: race picker that shows the full 2025 calendar, clean loading states so it never looks broken, and a shareable URL so you can send them a direct link to Monaco data.
Season race picker
Replace hardcoded Bahrain with a full 2025 season grid. Completed races are clickable, upcoming races are greyed out with "TBC" label. Clicking a race navigates to its replay view.
frontend
Loading states and error handling
Skeleton loader for the track map while data fetches. Friendly error messages when a race isn't available yet (not a raw 500). Toast for "Loading telemetry..." during replay initialisation.
frontend
Shareable race URLs
Route structure: /race/[year]/[raceName]/[session]. Deep-linkable so you can drop a URL in the group chat: "watch this — here's the Monaco replay". Critical for the friends demo.
frontend
Replay controls polish
Play/pause, playback speed (0.5×, 1×, 2×, 4×), lap jump buttons, and a timeline scrubber that shows key race events (pit stops, safety car, fastest lap) as markers.

Phase 4 — Feature completion
June 3  ·  Day 7
Depth features
Head-to-head mode
Two-driver comparison: gap delta chart over race distance, side-by-side tyre strategy, and synchronised positions on the track map. Huge for the "who was actually faster?" argument with friends.
frontenddata
Race events timeline
Horizontal timeline showing pit windows, SC/VSC periods, fastest lap moments, and flag events. Click any event to jump the replay to that moment. Data already available in FastF1 race control messages.
frontenddata
Sprint weekend support
Handle session type SQ (Sprint Qualifying) and S (Sprint) in the backend and frontend. 2025 has sprint weekends — make them selectable alongside the main race without breaking the data pipeline.

Phase 5 — Monaco GP testing
June 4–5  ·  Day 8 + Race day
Race day
Monaco GP starts Sunday June 8 (race), but qualifying is June 6–7. THE GRID's first live test is actually qualifying day — Q1/Q2/Q3 data will be available a few hours after sessions end. Plan to demo qualifying replay before the race even starts.

June 4: load 3+ 2025 races from scratch (no cache) and verify no 500s. June 5 morning: run the full friend demo flow — pick race → watch replay → open head-to-head. Time each step. Fix anything that needs clicking twice.
